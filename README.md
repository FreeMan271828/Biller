# BillCount (biller)

通过账单截图自动化生成记录。

本版本已完成 **PostgreSQL 持久化** 与 **全屏 TUI + CLI 终端交互**：数据模型（账单 / 计划 / 分类 / 月度记账）
通过 `sqlx` 落到 PostgreSQL，既能用交互式界面操作，也能用命令行子命令脚本化。

## 技术栈

| 用途 | 选型 |
| --- | --- |
| 语言 | Rust（edition 2024） |
| 数据库 | PostgreSQL + `sqlx` 0.8（运行时 SQL，无需编译期连库） |
| 异步运行时 | `tokio` |
| 交互式界面 | `ratatui` 0.30（crossterm 后端，原生支持 Windows 控制台） |
| 命令行 | `clap` 4（derive） |
| 时间 / 金额 | `chrono`；金额用自实现的「分」整型，避免浮点误差 |

## 目录结构（按服务拆分）

每个业务领域一个文件夹，内部固定 **`model` → `dao` → `service` → `tui`** 四层：

- `model` 数据结构，`dao` 只写 SQL，`service` 承载业务规则，`tui` 只做终端参数与输出；
- 领域之间**只允许通过对方的 `service` 交互**（例如账单领域靠 `BookService` / `CategoryService` 解析计划与分类）；
- 公共能力集中在最小的 `common` 层，交互式界面外壳在 `tui/`。

```
src/
├── main.rs              入口：解析参数 → 装配 service → 分发（CLI 或 TUI）
├── lib.rs
├── common/              最小化公共服务
│   ├── db.rs            连接池 / 建库 / 建表 / 约束错误翻译
│   ├── schema.sql       表结构（幂等，include_str! 编入二进制）
│   ├── money.rs         金额：分 ↔ 元
│   ├── time.rs          月份 / 时间解析
│   ├── table.rs         终端表格（中文按双列宽对齐）
│   └── types.rs         BillId / BookId / CategoryId / AmountType
├── bill_book/           计划领域      model｜dao｜service｜tui（一个计划 = 名字 + 类型（收入/开销）+ 可选上限）
├── category/            分类领域      model｜dao｜service｜tui（树状：父子 + 递归删除）
├── bill/                账单领域      model｜dao｜service｜tui
├── month/               记账周期领域  model｜dao｜service｜tui（月报按分类、年报按计划）
├── plan/                资金计划领域  model｜service｜tui（计划视图 + 覆盖面校验 + 日历额度）
├── bank/                银行流水领域  model｜dao｜service｜tui（招商银行流水 → 待核对账单）
└── tui/                 交互式界面外壳
    ├── app.rs           状态机（纯逻辑，可脱离终端测试）
    ├── input.rs         与终端库无关的按键抽象
    ├── event.rs         crossterm 事件 → 按键
    ├── view.rs          ratatui 渲染
    └── mod.rs           事件循环与终端初始化
```

## 快速开始

**零配置**：不带任何参数跑起来就行，默认用本地 SQLite 文件
`%USERPROFILE%\.biller\biller.db`（目录和文件都会自动创建）。

```bash
# 直接用（首次运行会自动建好本地库）
cargo run --

# 或者用命令行
cargo run -- bill add expense 12.34 --book 微信 --category 餐饮 --remark 午饭
cargo run -- month show --month 2026-10
```

想换库的话，三种方式任选：

```bash
# 1) 只这一次：命令行参数（postgres:// 或 sqlite: 开头都行）
cargo run -- --database-url "postgres://postgres:postgres@127.0.0.1:5432/biller" init
cargo run -- --database-url "sqlite:D:/我的账单/biller.db" init

# 2) 写进 %USERPROFILE%\.biller\config.toml（推荐，界面里改的也是它）
#    mode = "local" / "postgres"、sqlite_path、postgres_url

# 3) 界面里改：按 , 进设置 → 选「运维 · 数据库」→ e
#    第一项「模式」在 本地文件 / PostgreSQL 之间切，回车保存后界面立刻切过去
```

连接串优先级：`--database-url` > `DATABASE_URL` 环境变量（含 `.env`）
> `%USERPROFILE%\.biller\config.toml` > 内置默认（**本地 SQLite**）。

> **连不上也进得去界面。** 数据库没起来时不会直接退出，而是显示一张引导页，
> 告诉你当前目标是什么、该怎么填；按 `,` 进设置改好连接串，回车保存就切过去了。

### 设置页（数据库连接）

按 `,` 切到「设置」（再按一次 `,` 或 `Esc` 回到刚才那一页；顶栏一直有 `, 设置` 提示）。
**计划已经和账本合并**，所以设置页只留两件事：分类维护和数据库运维。设置页是「左菜单 + 右列表」两级：

- `↑` `↓` 在左边菜单里选分区（`▶` 标当前分区，整行反色）：
  **分类 → 运维 · 数据库**（日常记账在前，数据库运维沉到最后）；
- `Enter` 进右边的列表，`Esc` 退回菜单；进了列表后 `↑` `↓` 选条目、`Enter` 编辑；
- 切到别的页面再回来，会回到菜单态，不会停在半路。

| 分区 | 里头是什么 | 进列表后能用 |
| --- | --- | --- |
| ▶ 分类 | 分类树（缩进显示层级） | `a` 新增、`e` 改名/换父、`d` 删除 |
| ▶ 运维 · 数据库 | 主机 / 端口 / 用户名 / 密码（打码）/ 数据库 + 实际连接串 | 不需要进列表，直接 `e` |

页面级的两个动作在任何分区都能用：

- **`i` 初始化**：建库（不存在时创建）+ 幂等建表。程序启动时也会自动跑一次建表，
  所以后加的表 / 索引会自动补齐。
- **`t` 数据迁移**：打开一个「目标库」表单（默认预填当前连接）。
  确认后按顺序执行：建目标库 → 建表 → **把当前库的全部数据整库搬过去** →
  自动切换连接到目标库并把设置写进 `.env`。

  迁移的语义是「目标库 = 源库的完整副本」：

  - **目标库会被先清空再写入**（`TRUNCATE ... RESTART IDENTITY`），已有数据不会保留；
  - 主键、外键关系一起搬，**自增序列也同步校正**（`setval`），迁完接着插入不会撞主键；
  - 分类按父子顺序写入，自引用外键不会拦；
  - 整个过程在目标库的一个事务里，中途失败会整体回滚，**源库始终不动**。

  连接分区按 `e` 改完回车保存，写进当前目录的 `.env`，并**立即尝试切换**；
  连不上也不会丢设置（`.env` 已写好），旧连接继续可用，状态栏会说明原因。

> 密码以明文写进 `.env`（该文件已在 `.gitignore` 中忽略，请勿提交）。
> CLI 的 `biller init` 与设置页的 `i` 等价。

## 交互式界面（TUI）

`biller`（或 `biller ui`）在真实终端中打开全屏界面：顶部页签、中间表格、底部状态栏与快捷键提示。
**请在真实终端里运行**，不要重定向输出或通过管道调用，否则会给出明确的报错。

### 快捷键

一句话记住方向键：**`↑` `↓` 管当前页面，`←` `→` 管顶部页签。**
顶部一共 4 个页签，数字键直接跳：`1` 概览 · `2` 计划 · `3` 账单 · `4` 报表（月报 / 年报）。
设置不占页签：按 `,` 临时打开、再按一次退出（数据库运维是设置里的第三个分区）。

| 按键 | 作用 |
| --- | --- |
| `←` `→` / `Tab` / `1`-`4` | **切换页面**（概览 / 计划 / 账单 / 报表），顶部页签跟着走 |
| `,`（或 `6`） | 打开 / 收起**设置页**（分类 · 运维）；顶栏常驻 `, 设置` 提示 |
| `?` | 打开**帮助**：全部快捷键 + 「额度 / 已花 / 还剩 / 日额度」四个词的解释，任意键关闭 |
| `m` / `y` | **报表页**：切回月报 / 切到年报 |
| `↑` `↓` | **页面内部**移动：概览页换「正在查看的日期」，计划 / 账单列表选行，报表页月报选行，设置页选分区 / 选条目 |
| `PageUp` / `PageDown` | 概览页一次跨 7 天；**账单页翻整页**（一页放多少条跟终端高度走）；其他列表一次跨 10 行 |
| `Home` / `End` | 月初 / 月末（概览），列表首行 / 末行 |
| `Enter` | 概览页有流水待核对时**继续逐条核对**；账单页编辑选中的账单；设置页进列表 / 打开编辑 |
| `Esc` | 设置页从列表退回菜单、在菜单上再按则回到进来时那一页；关闭弹窗 |
| `s` / `w` | **仅概览页**：同步今天的 / 本周的银行流水 |
| `[` `]` | 上一个 / 下一个周期：普通页换月，**报表页切到年报时换年**（设置页没有月份，按下不生效） |
| `m` | 回到本月（并把年份复位）；在报表页同时切回**月报** |
| `a` | 当前页新增（**计划页新建计划**、账单页记一笔）；**设置页新增分类** |
| `e` | 编辑当前选中的记录；**计划页改这个计划的名字、类型与上限**；概览 / 报表页是「本月设置」，只改**起始金额**（额度去计划页） |
| `i` | **设置页**：初始化（建库 + 建表） |
| `t` | **设置页**：数据迁移（把当前库的数据整库搬到目标库） |
| `d` | 删除当前选中的记录 |
| `u` | **撤销最近一次删除**（只留最后一笔，`d` 之后状态栏会提示） |
| `x` | **账单页**：切换选中账单「是否计入日历」（`计` 列为 × 的不进支出日历，报表与本月收入照常计入）；**报表 · 年报**：展开 / 收起没有记录的月份 |
| `r` | 重新从数据库读取 |
| `q` / `Ctrl+C` | 退出 |

还没配好数据库时（引导页），键盘**只放行切页、`?` 帮助、`,` 设置和退出**——避免你对着表单填完才发现写不进去；
按 `,` 进设置、`e` 填连接串、回车保存即可。

表单内：`Tab` / `↑` `↓` 切换字段，`←` `→` 或空格循环切换选项。
**行尾带 `▾` 的是选择框**，按 `Enter` 展开完整候选列表（`↑` `↓` 移动、`Enter` 确定、`Esc` 取消）；
普通文本框上按 `Enter` 直接提交表单。
**「日期」字段留空表示今天，按空格填入上次用过的日期**；
**「金额」字段可以直接写算式**（`+ - * /` 与括号，如 `12.34+5`、`(10+2)*3`），**按 `=` 求值**
（忘了按也没关系，直接提交时同样会按算式计算）。

### 三个口径

| 页面 | 口径 |
| --- | --- |
| 概览 | **一屏三段**：顶部**本月**（已花 / 额度 / 还剩 + 进度条 + 日均 / 月底预计）→ 左 **支出日历**（绿/黄/红，图例写在边框标题里）+ 右 **今日**（`↑` `↓` 换日期：今日已花 · 今日还剩 ｜ 今日额度）与 **当日动账**（只列 `↑` `↓` 选中那天，和「今日」同一个日子）。银行同步状态只在底栏状态行里出现，按 `s` / `w` 动手 |
| 计划 | **收入在上、开销在下两个框**（框高随各自行数伸缩）：收入计划看 目标 / 已入 / 差距，开销计划看 上限 / 已花 / 剩余；右边实时校验**开销额度合计能不能覆盖本月收入**；开销额度合计同时充当支出日历的「本月上限」 |
| 账单 | **按日期 + 星期分组**（`10-26 周日 · 3 笔 · 支出 -120.00`），**一页放满视口**（终端越高看得越多），`PgUp`/`PgDn` 翻整页 |
| 报表 · 月报（`m`） | **收入置顶**（反色徽标 + 大字金额）+ 分类·计划成对的支出排行（`↑↓` 选一行）+ 该行明细 + 按分类收入 |
| 报表 · 年报（`y`） | **按计划**：计划收入/支出分布 + 逐月走势（没有记录的月份默认折叠，`x` 展开） |

### 计划 / 分类，各管一层

1.4 起**账本和计划合并成一件事**：一个计划 = 一个名字 + 一个类型（收入 / 开销）+ 一个可选额度。
记账时账单挂在某个计划名下，那个计划的「已入 / 已花」就自动涨 —— 不再需要先把账本做好、再去计划页
按分类把预算和账本绑起来。

| 层 | 回答的问题 | 例 | 不做什么 |
| --- | --- | --- | --- |
| 计划 | **钱记在哪个计划下 + 这个月给多少** | 工资（收入，目标 8000）、日常开销（开销，上限 3000） | 不管这笔钱花在什么上 |
| 分类 | **这笔钱花在什么上**（可两级） | 餐饮 → 外卖 | 不设预算、不当账户用 |

**计划分两种类型，分开显示、分开算**：计划页先收入、后开销（两块高度各自跟着行数伸缩），
CLI 的 `plan show` 也是两段。

| 类型 | 回答的问题 | 三列 | 例 |
| --- | --- | --- | --- |
| **收入计划** | 这个月该进来多少 | 目标 / 已入 / **差距**（还差多少；超额完成算好事，不标红） | 工资（目标 8000）、外快 |
| **开销计划** | 这些钱怎么分出去 | 上限 / 已花 / **剩余**（超了标红） | 房租 2500、吃饭 1500 |

两种都有「设不设额度」的自由，这也是「额度可选」的意义：

| 形态 | 额度列 | 累计 | 例子 |
| --- | --- | --- | --- |
| **有目标 / 上限** | 收入填目标、开销填上限 | 按这个计划名下的本月账单自动算 | 工资 8000、日常开销 3000 |
| **不设** | `不设`（收入）/ `不限`（开销） | 只累计，不算差距 / 剩余（显示 `—`） | 外快、存款 |

**已入 / 已花口径**：这个计划名下的、本月的账单之和 —— 开销计划剔除「不计入日历」的支出，收入计划不剔除（`excluded` 只影响支出，摘出去不改收入）。
一条 SQL 都不用写复杂的月份聚合 —— 先把当月账单捞出来，在内存里按计划分组。
所以**旧版按分类对账的预算块**（`plan.items` JSON）迁移后已花从 0 起算，历史账单不再自动归属。

### 资金计划（新建、改类型 / 名字 / 额度）

| 操作 | TUI | CLI |
| --- | --- | --- |
| 新建 | 计划页 `a`，填名称 + **类型（开销 / 收入）** + 额度（留空 = 只累计） | `biller plan add --name 房租 --limit 2500`（不传 `--kind` 默认开销）<br>`biller plan add --name 工资 --limit 8000 --kind income` |
| 改名字 / 改类型 / 改额度 | `↑` `↓` 选中后 `e`（或 `Enter`）；类型用 `←` `→` / 空格切 | `biller plan set --name 房租 --limit 2800`<br>`biller plan set --name 房租 --kind income`（两个参数可以一起给） |
| 取消额度 | `e` 把「额度」清空 | `biller plan set --name 房租 --limit -` |
| 删除 | 选中后 `d`（计划下还有账单会被拒绝） | `biller plan remove --name 房租` |
| 看 | 计划页（收入框在上、开销框在下，各看各的列） | `biller plan show [--month 2026-10]`（收入计划一段、开销计划一段） |
| 只校验 | 计划页右侧「覆盖校验」 | `biller plan check [--month 2026-10]`（盖不住时退出码 `1`） |

**额度能写算式**（`9000/3`、`(2500+300)*2`），提交时求值 —— 开销填的是上限，收入填的是目标。

**覆盖校验**（计划页右侧常驻）只拿**开销计划**去比收入 —— 收入计划是钱的来路，不能拿去当开销额度：

| 结论 | 条件 | 显示 |
| --- | --- | --- |
| ✔ 能覆盖 | 开销额度合计 ≤ 本月收入 | 「还剩 X」；命令行再给出计划占收入的百分比 |
| ✖ 盖不住 | 开销额度合计 > 本月收入 | 「差 X」；命令行再给出计划占收入的百分比 |
| 还没设开销额度 | 所有开销计划都不设额度 | 只提示「留空额度的开销计划只累计，不参与校验」 |

**收入口径**：该月所有方向为 `income` 的账单之和（工资记一笔就够）。
不计入日历（`excluded`）的账单**照样算收入** —— 摘出去只影响日历，不改报表口径。

**日历额度 = 所有有上限的开销计划之和**（收入计划和「不设上限」的计划都不参与，否则等于给流水账也发额度）：

| 项 | 含义 |
| --- | --- |
| 本月额度 | 有上限的**开销**计划之和，例如 `5500` |
| 日额度 | **= 额度 ÷ 当月天数**，例如 `5500 / 31 = 177.42` |
| 累计额度 | 到某天为止的**额度余额** = `日额度 × 天数 − 累计开销`；花超前了是**负数** |

概览页的**支出日历**一天一格：

| 颜色 | 含义 |
| --- | --- |
| 灰 | 这天没有支出（含还没到的日期） |
| 🟩 绿底 | 有支出，且当天没超**日额度** |
| 🟨 黄底 | 当天支出**超了日额度** |
| 🟥 红底 | **到当天为止累计**已经超过合计（本月上限），从这天起一路红 —— 超支判断只有这一种，不再有「只看当天」模式 |

**用底色而不是字色**：终端里黄字和绿字很容易看混，整块色块一眼就分得开。

**选中态是「深蓝底 + 近白字」**：日历选中那天、计划 / 账单 / 月报排行的整行、设置页当前分区、
报表的「月报 / 年报」子页、弹窗里当前那一项，全用同一套选中配色。选中行里的语义色（收入绿、
支出红、备注灰）在这一行**统一让位** —— 底色压暗、字提亮，选中的那一行反倒是整屏最好读的；
选中框的**边框**仍是浅蓝（`ACCENT`），「哪个框有焦点」和「选了哪一行」用两种信号分开说。

顶部「本月」一条给出 `已花 / 额度 / 还剩` + 进度条 + `日均 / 月底大约`，
下面的「今日」面板给出 `今日已花 / 今日还剩`。日均的分母是**已经过去的天数**（看历史月份时取整月天数），
否则月初看会低得离谱。

> **老数据自动迁移（1.4）**：1.3 及之前，计划是 `app_state` 里 `plan.items` 的一串 JSON 块。
> 1.4 打开界面时会把这些块整批搬成计划：块名 → 计划名、块金额 → 上限，
> 搬完删掉 `plan.items` / `plan.expected` / `plan.savings` 并写下 `plan.migrated` 标记，
> 之后重复打开不会翻倍。更早的「预计金额 / 攒钱金额」两个标量也在这条路径上，
> 会先折成「日常开销 = 预计 − 攒钱」「存款 = 攒钱」再搬。

### 计入日历 / 不计入日历

报销、代付、走账这类**过手钱**只该从**支出日历**里摘出去（否则日历上那天会虚高、
日额度的判断也会失真）。两种改法：

- 账单页选中后按 `x`（`计` 列 `✓` ⇄ `×`）；
- 或者按 `e` 打开**账单详情**，把「计入日历」改成「不计入」。

⚠️ **口径边界**：`excluded` **只影响支出日历（日额度、日均、当日开销）**；计不进日历的钱**照样算进本月收入**，也不改计划合计。
**月报 / 年报始终全额计入**——报表是"这个月到底花了多少"，不该被日历的口径改写。
数据库里对应 `bills.excluded` 列，
老库由 `init_schema` 里的幂等 `ALTER TABLE ... ADD COLUMN IF NOT EXISTS` 自动补上。

### 几个行为说明

- **新增账单时，计划与分类是从数据库自动读取的选择框**（分类带层级缩进），不用手打名称；
  **焦点默认落在「金额」**（打开表单直接输钱），字段顺序按记账动线排：**金额 → 分类 → 计划 → 日期 → 备注**；
  **分类与计划都自动选中上次用过的那个**（上次那个若已被删除，回落到「默认」）；
  存完一笔会**留在当前页签**（连记几笔不用每次切回来）；概览页的选中日期会挪到刚记的那一天，回到概览就能在日历上看到它落进哪一格。
  按 `Enter` 在「分类 / 计划」上展开候选，
  **候选列表贴在表单右侧**（窄屏放不下就放到下方），表单本身不会被盖住。**「日期」默认留空（即今天）**，把光标移到日期字段后**按空格**
  才会填入上次用过的日期。三项记忆（日期 / 计划 / 分类）都记在数据库的 `app_state` 表里，换会话、重启都还在。
- **默认值永远不会是空的**：计划候选为空时预填「默认」，分类候选为空时同样预填「默认」，
  提交时由 service 自动建出来（`DEFAULT_BOOK` / `DEFAULT_CATEGORY`）——空库也能直接记账，
  不会出现「计划是空的、点提交被拒绝」这种死路。真正的文本框只在候选列表拿不到时出现。
- **分类是树状的**：列表按父子层级缩进显示；新增/编辑分类时，父分类同样是选择框，
  并且会自动排除「自己与自己的子孙」，从源头上避免形成环（service 层还有一道防环校验）。
- **删除分类会提示连带影响**：若该分类下有子分类，确认框会列出将被一并删除的子分类名称；
  只要子树里还有账单，删除会被拒绝并告知账单数量，避免顺手删掉账目。
- **账单页分组 + 分页**：先按**日期**倒序分组，每天一行日期头（`2026-10-26 周日 · 3 笔 · 支出 -120.00 · 收入 +0.00`），
  下面才是当天的账单；跨天不会混在一起。
  一页放多少条**跟着终端高度走**（`终端高度 − 6`，见 `App::bill_page_budget`），窗口拉高就多显示几笔，
  不再写死 10 条把下半屏空着；`PageUp`/`PageDown` **翻整页**，`↑` `↓` 选到页外时自动跟到那一页。
  切页只在「日期头 + 行」的单位上算，必要时才把某一天断成两页，新页会重新出一行日期头，翻到一半也知道自己在哪一天。
  底部常驻「第 i/n 条 · 第 p/q 页」，翻到哪一条、第几页一眼知道。
- **列表跟随选中滚动**：计划 / 分类 / 月报排行的标题里会显示「第 x/n」，
  `↑` `↓`、`PageUp`/`PageDown`、`Home`/`End` 移动时选中行始终留在可见区域内，不会走出屏幕。
- **概览顶部单独突出「今日剩余」和「今日开销」**：
  剩余 = 本月起始金额 + 截至今日收入 − 截至今日支出，记到未来日期的账单不计入。
  翻到别的月份时这里会提示「今日数据只在查看本月时显示」——账单只加载当前查看的那个月，
  看别的月份时今天的账根本不在手上，与其显示 0 不如说清楚。
- 月报与年报的分工是刻意的：**月份看分类 + 计划**，**年份看计划**。
  月报的支出排行是「分类 @ 计划」成对比较，而不是只按分类汇总——同一类开销常常分散在多个计划里，
  只按分类会把「钱从哪本账走」抹平，房租这类集中在一本账上的大头就看不出来了。
  `↑↓` 选中任意一行，右侧明细就只列这一对（分类 + 计划）的账单。
- 所有构成表都带 **`占比` 百分比 + 条形图**（月报的支出排行、年报按计划）
  表头标题里还会给出该项口径的**合计**；条形图宽度按可用列宽自适应，窄终端也不会挤爆。
  年报的逐月走势再给一条「以全年最高月为满格」的支出分布条，哪几个月花得多一眼可见。
- **概览讲「今天」，月报讲「本月」**：概览顶部只有三个数（已花 / 额度 / 还剩）+ 一条进度条，
  右侧「今日」也只给两个数（今日已花 / 今日还剩）；整月的构成与「起始金额 / 收入 / 结余」只在月报出现，
  两页不会看到两张一样的表。概览右下的「当日动账」只列选中那一天的账单，`↑` `↓` 换日时和上面的「今日」一起动。
- **帮助不占版面**：概念解释（额度 / 已花 / 还剩 / 日额度）、计划怎么分、全量快捷键都在 `?` 里，
  页面右栏只留当下要看的表。
- **计划就是 `bill_books` 里的一行**：`plan_limit`（额度，可空）与 `plan_kind`（`income` / `expense`）
  两列落在账本表上，不额外建表；老版本的 `plan.items` JSON 在首次打开时整批迁成计划（迁移标记 `plan.migrated`）。
- **计划页的校验是即时的**：每加 / 改 / 删 / 切类型一次都会重新算「开销额度合计 vs 本月收入」；
  盖不住时覆盖校验卡直接标红，不用去翻别的页。
- 所有金额都带**千分位**显示（`1,234.56`）。这只是展示：输入侧本来就接受 `1,234.56`，
  表单回填后再提交会被 `parse_amount` 原样吃回去（有往返测试兜着）。
- 账单列表与月报明细里的**时间只展示到天**（`YYYY-MM-DD`）；具体时刻仍然完整存在数据库里，
  月报/年报的月份归属也照旧按 UTC 计算。

### 两个后端怎么共存的

一套代码同时支持 PostgreSQL 与本地 SQLite，做法是：

- **连接池**统一用 `sqlx::Any`（`common/db.rs` 的 `Pool`），`connect()` 看连接串前缀
  自动认后端（`postgres://…` 或 `sqlite:…`），SQLite 会顺手把父目录建出来；
- **建表语句两份**：`common/schema.sql`、`common/schema_sqlite.sql`，
  `init_schema()` 按后端挑；
- **占位符**：全项目统一写 `?`，发起前由 `Pool::shared()/sql()` 改写成 PostgreSQL 的 `$n`
  —— `Any` **不会**替你做这件事（直接发 `?` 给 PG 会报 `syntax error at end of input`）；
- **时间戳**：`Any` 不支持 chrono 类型，所以时间/月份全程以 ISO 文本进出：
  PG 侧读用 `to_char(... 'YYYY-MM-DD HH24:MI:SS')`、写用 `?::timestamptz`，
  SQLite 侧就是普通 TEXT 列；月份筛选两边绑同一个 `YYYY-MM-DD` 文本，
  SQLite 侧用 `substr(?, 1, 7)` 取前缀比对，这样绑定链不用分叉；
- **SQLite 的差异点**：布尔是 0/1 的 INTEGER（读出来按整数处理，写用 `(? = 1)`）、
  `IS NOT DISTINCT FROM` 要换成 `IS`、`ANY(?)` 绑不了数组（改成 `IN (?, ?, …)`）、
  URL 必须带 `?mode=rwc`（否则 sqlx 不会创建文件，报 `unable to open database file (code 14)`）；
- **整库数据迁移**目前只支持 PostgreSQL → PostgreSQL，碰到 SQLite 会明确报错而不是悄悄跑一半。

## 数据库改动检查清单（双后端 PostgreSQL / SQLite）

项目用 `sqlx::Any` 同时支持两个后端。踩过的坑都收敛成下面 8 条，**改数据库前先过一遍**：

1. **连接串**：本地模式只用 `common::db::sqlite_url()`（自动带 `?mode=rwc`），不要手拼 `sqlite:`，否则首次运行报 `code 14 unable to open database file`。
2. **占位符**：所有 SQL 统一写 `?`，并经过 `pool.shared()` / `pool.sql(pg, sqlite)`。**禁止**裸 `sqlx::query("... ? / $n ...")`——`Any` 不会把 `?` 转成 `$n`，直接发给 PostgreSQL 会报 `syntax error at end of input`。PG 专有语句（`ensure_database`、`migrate_all`）必须在 `DbKind` 守卫后局部使用。
3. **绑定个数**：`.bind()` 数量必须与 SQL 里每个 `?` 一一对应。WHERE 里同一条件出现两次（`(? IS NULL OR col = ?)`）就要绑两次——改完 SQL 先数占位符。
4. **时间/日期**：只以 ISO 文本进出（`YYYY-MM-DD HH:MM:SS` / `YYYY-MM-DD`）。PG 读用 `to_char(... AT TIME ZONE 'UTC', ...)`、写用 `?::timestamptz` / `?::date`；月份参数一律先归一到当月 1 号（`first_day_of_month`）再进 SQL。
5. **布尔**：读写都走整数——读 `CASE WHEN col THEN 1 ELSE 0 END`（SQLite 直接读 0/1 后解成 `i64 != 0`），写 `(? = 1)`。禁止 `.bind(bool)` 或把列解成 `bool`（SQLite 会报 `Rust type bool is not compatible with SQL type BIGINT`）。
6. **方言差异**：只放在 `pool.sql(pg, sqlite)` 里。数组用 `IN (?, ?, ...)` 动态拼接（`ANY(?)` 在 Any 下绑不了数组），`IS NOT DISTINCT FROM` 在 SQLite 用 `IS`。
7. **schema 同步**：改表/列/索引必须同时改 `common/schema.sql` 与 `common/schema_sqlite.sql`；新增列还要在 `common/db.rs` 的 `SQLITE_ADDED_COLUMNS` 登记老 SQLite 库的补列 DDL（`schemas_stay_in_sync` 测试会挡住漂移）。
8. **事务与幂等**：多步写入共用一个事务（DAO 加 `*_in(tx)` 变体）；导入类写入先做幂等预检（指纹/唯一键）。新增 SQLite 测试必须真跑；PG 路径用 `BILLER_TEST_DATABASE_URL` 门控，**发版前用真 PostgreSQL 跑一次**：
   ```bash
   BILLER_TEST_DATABASE_URL=postgres://postgres:postgres@127.0.0.1:5432/biller cargo test
   ```
